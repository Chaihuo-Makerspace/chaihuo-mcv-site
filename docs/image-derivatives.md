# Image Derivatives

Large public images are served through small WebP derivatives generated by
sharp scripts. All derivative outputs are **gitignored and rebuilt at
dev/build time** (`pnpm dev` / `pnpm build` run the generators), so no
dependency install is needed in content-sync workflows.

- **Yuque covers** — synced covers are 960px originals (~100KB median, 5MB
  total) but the route page renders them at 36–132px.
  `scripts/generate-cover-thumbs.mjs` writes `public/yuque-journals/thumb/`
  (208px) and `card/` (480px) WebP derivatives. `withCoverDerivatives()` in
  `src/lib/journals.ts` checks each file with `existsSync` and falls back to
  the original, so a missing derivative degrades instead of 404-ing.
- **People avatars** — a few `public/people` photos are camera originals (up
  to 2MB) but render at 32–128px in the home `RoleTimeline`.
  `scripts/generate-people-avatars.mjs` writes `public/people/avatars/64/` and
  `avatars/256/` WebP derivatives. `withAvatarDerivatives()` in
  `src/lib/people.ts` resolves them with an `existsSync` fallback to the
  original; call it in `.astro` frontmatter only (at build time
  `import.meta.url` points into `dist/server`, so it also tries
  `process.cwd()/public`). Aspect ratio is preserved (no square crop) because
  the ye-kaiwei avatar transform is tuned against the portrait original.
- **Hero carousel** — `scripts/generate-hero-variants.mjs` writes 768px WebP
  mobile variants to `public/heroes/mobile/`.
- **Deconstruct cards** — `scripts/generate-deconstruct-thumbs.mjs` writes
  224px WebP thumbs to `public/deconstruct/solutions/thumb/`.

Hero and deconstruct derivatives are resolved in `.astro` frontmatter via
`createDerivativeResolver()` from `src/lib/derivatives.ts` (same two-candidate
`existsSync` fallback as `src/lib/people.ts`; `getPublicImageSize()` there
reads width/height for CLS attrs). The hero carousel picks desktop vs mobile
background with mutually exclusive `hidden md:block` / `md:hidden` divs —
`display:none` backgrounds are never downloaded, so there is no double-fetch —
and the first slide is preloaded with `media`-scoped `<link rel="preload">`
via the `head` slot in `BaseLayout.astro` (home pages only).
